Bouwen in HTML & CSS

Je geteste prototype wordt een echte website. Je zet je ontwerp om in HTML voor de inhoud en structuur, en CSS voor de vormgeving.

📌 In het kort

Je zet je geteste prototype om naar een website: HTML voor de inhoud en structuur, CSS voor de vormgeving. Je bouwt mobile first, volgt je stijlgids en kijkt vaak in de browser.

💡Wat is het?

Een werkende website, gebouwd met HTML en CSS op basis van je (verbeterde) prototype.

🎯Doel

Je ontwerp werkelijkheid maken en leren hoe een website technisch in elkaar zit.

📄Je levert op

De broncode (netjes geordend), een online versie of link, en een korte uitleg van hoe je je prototype hebt vertaald naar code.

Belangrijke begrippen
HTMLCSSsemantische HTMLmappenstructuurCSS-variabelenmobile firstmedia queryresponsive

👥 In challenge 3 · Tweede helft Realisatie

Jij bouwt de voorkant (HTML en CSS), je Software-groepsgenoten vaak de achterkant. Spreek vroeg af hoe jullie bestanden delen, bijvoorbeeld met Git, en hoe de onderdelen op elkaar aansluiten.

Workshop in Canvas: Workshop Introduction to Web Design · Workshop Advanced frontend design · Workshop Version control (GIT) · Bekijk de planning voor challenge 3 →

Aanpak

  1. Structuur eerst. Maak een map met per pagina een HTML-bestand, één CSS-bestand en een map voor afbeeldingen.
  2. Inhoud in HTML. Zet alle inhoud erin met de juiste semantische elementen: <header>, <nav>, <main>, <section>, <h1> tot <h3>, <footer>.
  3. Vormgeving in CSS. Begin bij de kleuren en lettertypes uit je stijlgids. Gebruik CSS-variabelen, dan pas je een kleur op één plek aan.
  4. Mobile first. Bouw eerst de mobiele versie, en voeg met een @media-query de aanpassingen voor grotere schermen toe.
  5. Vaak controleren. Bekijk je pagina na elke stap in de browser en op je telefoon.

Doel

Pas als je ontwerp gebouwd is, kunnen gebruikers het echt gebruiken. Door zelf te bouwen leer je ook wat wel en niet makkelijk te maken is, en dat maakt je een betere ontwerper.

🔧 Voorbeeld De Schroef: de kaart voor de studentenavond

HTML:

<section class="event">
  <p class="label">Studentenavond</p>
  <h2>Fix &amp; Friet</h2>
  <p class="date">Donderdag 5 november, 19:00 tot 22:00</p>
  <p>Neem je kapotte spullen mee. Repareren is gratis, de friet ook.</p>
  <a class="button" href="studentenavond.html">Aanmelden</a>
</section>

CSS, met de kleuren uit de stijlgids:

:root {
  --geel: #FFC93C;
  --blauw: #1B2A4A;
}

.event {
  background: white;
  border-left: 6px solid var(--geel);
  padding: 16px;
}

.button {
  display: inline-block;
  min-height: 44px;          /* goed aan te tikken op mobiel */
  padding: 12px 20px;
  background: var(--geel);
  color: var(--blauw);
  border-radius: 22px;
}

/* Vanaf tablet: de kaarten naast elkaar */
@media (min-width: 768px) {
  .cards { display: flex; gap: 24px; }
}

🤖 GenAI bij dit product

Slim inzetten

  • Laten uitleggen wat een stuk code doet, of waarom iets niet werkt.
  • Een foutmelding of onverwacht resultaat laten verklaren.
  • Je code laten reviewen: is de HTML semantisch, kan de CSS korter?

Pas op

  • Je moet elke regel code die je inlevert kunnen uitleggen. Kun je dat niet? Dan heb je het niet geleerd.
  • Laat AI geen complete pagina's schrijven om te kopiëren. Vraag om uitleg, en schrijf de code zelf.
  • AI-code werkt niet altijd en is soms verouderd. Test alles in de browser.

Voorbeeldprompt

Ik leer HTML en CSS. Mijn twee kaarten staan onder elkaar, maar ik wil ze vanaf 768 px breed naast elkaar. Dit is mijn code: [code]. Geef me nog geen oplossing, maar leg uit waar het probleem zit en geef een hint, zodat ik het zelf kan oplossen.

Leg in je AI-verantwoording vast wat je met AI hebt gedaan en wat je zelf hebt aangepast.

💡 Laat AI je leraar zijn, niet je ghostwriter

Vraag AI om hints in plaats van oplossingen, of laat het je code uitleggen alsof je een beginner bent. Schrijf wat je leert in je eigen woorden in een logboek. Zo groeit je eigen kennis, en heb je meteen materiaal voor je AI-verantwoording.

⚠️ Veelgemaakte fouten

  • Alles in <div>'s in plaats van semantische HTML.
  • Kleuren en lettertypes die afwijken van je prototype en stijlgids, zonder reden.
  • Alleen op een laptopscherm kijken en pas aan het eind ontdekken dat de mobiele versie niet werkt.
  • Code van AI of internet overnemen die je niet begrijpt.

Checklist

  • Mijn website is gebouwd met HTML en CSS en volgt mijn verbeterde prototype.
  • Mijn bestanden zijn netjes geordend en ik gebruik semantische HTML.
  • Mijn website werkt op mobiel en op een groter scherm.
  • Ik kan elke regel van mijn code uitleggen.
